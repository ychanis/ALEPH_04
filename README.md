# 오늘의 서울 기온 — ALEPH 과제 4

공개 기상 데이터를 조회하고, 날짜별로 저장한 값과 이전 기록의 차이를 보여주는 정보판입니다. 데이터를 받지 못했을 때는 마지막 정상값을 유지하면서 실패 원인과 다음 행동을 안내합니다.

## 결과물

- [공개 정보판](https://seoul-daily-signal.ksyji123.chatgpt.site)
- [GitHub 저장소](https://github.com/ychanis/ALEPH_04)

## 데이터의 의미

MET Norway의 공개 기상 API에서 서울 중심 좌표의 현재 시간대 기온 예측값을 가져옵니다.

- 위치: 위도 37.5665, 경도 126.9780
- 단위: °C
- 기록 시간대: Asia/Seoul, KST
- 출처 시각: 기상 모델의 예측 대상 시각
- 조회 시각: 서버가 실제 응답을 받은 시각

표시하는 값은 기상 모델의 예측값이며, 현장 관측소의 실측 기온은 아닙니다.

[공개 원천 API](https://api.met.no/weatherapi/locationforecast/2.0/compact?lat=37.5665&lon=126.9780)

## 주요 기능

### 실제 데이터 조회와 저장

값·단위·출처·출처 시각·조회 시각·기준 시간대를 표시합니다.

같은 KST 날짜에 여러 번 성공하면 기존 일별 기록을 갱신하고, 다음 날짜에 성공하면 새 기록을 추가합니다. 실제 기록은 서버의 Cloudflare D1에 저장되므로 브라우저를 닫아도 유지됩니다.

제공처의 캐시 유효기간에는 저장된 응답을 재사용합니다. 재사용한 데이터를 새로운 조회로 표시하지 않고 기존 조회 시각을 유지합니다.

### 실패 상태 처리

다섯 종류의 실패를 구분하여 설명과 다음 행동을 표시합니다.

| 실패 종류 | 오류 코드 | 다음 행동 |
|---|---|---|
| 느린 외부 응답 | timeout | 잠시 뒤 다시 시도 |
| 외부 원천의 401/403 거절 | auth | 출처의 이용 상태 확인 |
| 호출 횟수 제한 | rate_limit | 기다린 뒤 다시 시도 |
| 네트워크 연결 실패 | offline | 연결 상태 확인 |
| 응답 형식 변경 | schema_error | 출처 응답 형식 확인 |

실패하면 정상 저장값을 덮어쓰거나 지우지 않습니다. 마지막 정상값에 오래된 값 표시를 붙이고 다시 시도 버튼을 제공합니다.

### 원자료 대조

날짜별로 원자료·정규화 저장값·화면값을 펼쳐 볼 수 있습니다. 변화값은 다음 규칙으로 계산합니다.

**변화값 = 최신 날짜의 저장값 − 이전 날짜의 저장값**

두 날짜가 연속하면 ‘어제 대비’, 날짜가 떨어져 있으면 ‘이전 기록 대비’로 표시합니다.

## 실제 이틀 기록 확인

2026년 10월 2일 확인 당시, 같은 공개 원천에서 조회한 서로 다른 KST 날짜의 기록이 정확히 2건 보존되어 있었습니다.

| KST 조회 날짜 | 출처 시각(KST) | 조회 시각(KST) | 저장값 |
|---|---|---|---:|
| 2026-10-01 | 09:00:00 | 09:59:38 | 16.5°C |
| 2026-10-02 | 14:00:00 | 14:35:26 | 20.8°C |

**20.8 − 16.5 = +4.3°C**

두 기록의 원자료와 저장값, 단위, 출처 URL, KST 날짜가 일치하는 것을 확인했습니다. 조회 시간대가 다르므로 이 변화값은 같은 시간대의 기온 차이가 아니라, 두 날짜에 저장한 값의 차이입니다.

위 표는 확인 당시의 기록입니다. 같은 날짜에 새 조회가 성공하면 해당 날짜의 값과 변화값이 갱신될 수 있습니다.

## 공식 합성 검사

실제 데이터와 합성 검사 상태는 분리되어 있습니다. 합성 날짜와 값은 실제 이틀 기록을 대신하지 않습니다.

- 공식 package ID: `aleph-t04-real-information-board-public-contract-v2`
- 공식 자산 17개 파일의 SHA-256 대조 완료
- 정상·실패·복구 fixture 9종 검사 통과
- 같은 날짜 세 번 재실행 및 다음 날짜 저장 검사 통과
- KST 자정의 날짜 구분 검사 통과

각 실패 버튼은 공식 D1-A → D1-B를 재생한 뒤 해당 실패를 적용합니다.

| 단계 | 마지막 정상값 | 일별 행 수 | 상태 |
|---|---:|---:|---|
| D1-A 정상 | 100 pt | 1 | fresh / none |
| D1-B 재조회 | 105 pt | 1 | fresh / none |
| 다섯 실패 각각 | 105 pt | 1 | stale / 해당 오류 |
| D2 복구 | 120 pt | 2 | fresh / none |

복구를 반복해도 중복 행이 추가되지 않습니다. 합성 초기화는 실제 저장 기록에 영향을 주지 않습니다.

[공식 합성 검사 꾸러미](https://aleph-omega.vercel.app/assets/studio-task-assets/t04-real-information-board/t04-real-information-board-public-v1.zip)

## 확인 방법

1. ‘실제 데이터’ 탭에서 일별 기록과 날짜별 원자료 대조를 확인합니다.
2. ‘합성 실패 검사’ 탭에서 실패 종류를 선택하고 105 pt와 오래된 값 표시를 확인합니다.
3. ‘다시 시도 · D2 복구’를 누르고 120 pt·2행·fresh/none을 확인합니다.

‘전체 자동 검사’ 버튼으로 정상 저장, 다섯 실패, 반복 복구의 판정 결과도 확인할 수 있습니다.

## 사용 기술과 코드 구성

- 화면: React, TypeScript, CSS
- 실행 환경: Vinext, Cloudflare Workers
- 실제 기록 저장: Cloudflare D1

| 경로 | 역할 |
|---|---|
| `app/page.tsx` | 정보판 화면과 합성 검사 조작 |

| `db/schema.ts` | 저장 테이블 정의 |
| `drizzle/` | DB 마이그레이션 |
| `public/t04/` | 공식 합성 자산과 해시 확인 결과 |

```bash

```
